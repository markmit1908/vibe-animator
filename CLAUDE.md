# CLAUDE.md

Interactive Three.js animation of refuelling a hex-block (HTGR-style) reactor core,
used to illustrate the concept. Delivered live in a browser.

## Layout (after the SolverKit migration)
- `app/` is the app (SolverKit: Home, vault, editor frame; see `app/CLAUDE.md`). The shared core is in `src/` and
  imported by the app; `src/studio/studio.ts` mounts it into the Studio view for one model (`StudioIO`: `edit`
  → ctx.edit autosave, `fileUrl` → `/api/files/<vault path>`, `assist` → SolverKit's key proxy, `mountAssist` → SolverKit's
  AssistPanel, `putThumb` → the Home card image).
- Animations are model files in the vault (`src/model/file.ts`); there is no `scenes/` or `scripts/` any more.

## Commands
- `npm run drawings -- "<animation>" [sheets]` / `--all`: batch drawing sheets (SVG + PDF) into the vault, headless; needs the app running
- `npm run dev`: the app (server + web on :5174)
- `npm run typecheck`: `src/` and `app/`. Run it after every TS change.
- `npm run test:server`: the app server's pytest

## Architecture
- the model's `scene` → `src/scene/build.ts` → `BuiltScene` (registry of animatable objects by id, slots, columns, locations, clip planes)
- the model's `.anim` script → `src/script/anim.ts` → `src/timeline/compile.ts` → a flat list of `Tween`s and `StepEvent`s (label, cutaway, thumbnail)
- `src/timeline/player.ts`: `seek(t)` resets every registered object to its initial state and re-applies every tween up to t. It runs **every frame**, so playback is stateless and scrubbable. Never mutate animated state outside tweens.
- The compiler simulates a "virtual state" so each tween knows its from-value. `pick`/`place` expand into machine moves; the machine carries whatever it `held`s.
- Cutaway (`src/view/cutaway.ts`): a `Cut` = mode (none/half/quarter), sides removed (`x`, `-z`…) and a centre (`at`); shells and CAD are clipped with the shared `clipPlanes` (each part material needs `clippingPlanes` and `clipIntersection: true`; material clones must keep the live planes – `clone()` copies them). Core blocks inside the cut region are hidden whole. Reapplied each frame (script cut or the Controls' cut) by `applyCut` in studio.ts. Keep uncut: `model.cutKeep` (ids / @groups / ~names, applied to every cut) ∪ a script cut's `keep` (ids, resolved by the compiler) → `keptRoots` (memoised; `regVersion` bumps when shapes rebuild) → `Uncut` (cutaway.ts): kept drawables get an unclipped material twin (or `ownMat` ones lose their planes in place) and `userData.uncut`, which the part passes read per draw (`noClip` in caps.ts: unclipped in the normal pass, discarded from cap sums); kept core blocks stay visible.

- CAD (`scene.cad_models`, vault paths) is loaded **before** compiling (top-level await), so scripts can target CAD node ids (`<model>/<child>/…`).
- Player resets only `tl.touched` ids each frame. Visibility = not faded (script) AND not cut (cutaway) AND not `userData.userHidden` (tree toggle) AND not `userData.removed`. Keep all four when touching `.visible`. `setOpacity` marks a material transparent only while it's see-through.

- Part state (`src/scene/state.ts`): working `state` = explicit `locked`/`hidden` flags by id (inherited by descendants) + `placements` (gizmo moves, local p/q). Named snapshots (flags + camera + placements) and groups live in the model file (`snapshots`, `groups`); `setStore` loads them, Save writes through `setStoreWriter` → `io.edit`. Lock/hide/placement changes autosave into the active snapshot (`persistWorking()` in studio.ts), as do group changes; the snapshot bar's Save also records the camera. `applyPlacements()` resets every registry object to `userData.homeP/homeQ`, then applies placements; Player captures script start positions after that. `reconcile()` in studio.ts applies them. Locked → `matrixAutoUpdate=false` (and `matrixWorldAutoUpdate=false` for fully locked subtrees). Locked + hidden CAD → `CadManager.suppress` frees geometry; `restore` reloads it from the .glb by id.
- User groups: `store.groups` (name → member ids, ancestor-covered members dropped), saved in the model's `groups`, shared by all snapshots. Folders (`store.folders` / model `folders`: path "a/b" → group names; implied parents are made explicit before a move) are tree-only: the compiler never sees them; a folder row's spec is its groups (`@a, @b`); renaming/deleting a group updates them (tree and `applyGroupChanges`). Tree selection: ⌘/Ctrl-click toggles a row, Shift-click selects the visible rows from `anchor` (the last clicked) – `selectRange`. Scripts expand `@name` in `resolveTargets`. Compiler virtual state is WORLD space (`getWorldPosition`); tweens convert to parent-local, assuming parents of moving parts are static.
- Changing locks recompiles the script. Scripts may not move/rotate/colour locked objects (`state(id, motion)`); blank/fade/hide may. `lockedIn()` in studio.ts records every locked part a script animates (Unlock fix, assist proposals).

- `scene.generated: false` in the model builds the parametric reactor and then drops it (lights and grid stay). The registry then holds CAD only. With no leading `camera` step the view frames everything loaded.

- `.anim` scripts: `src/script/anim.ts` (parser → engine actions, keeps source ranges), `src/view/scriptPanel.ts` (CodeMirror 6, SolverKit ModelText patterns), `src/script/edit.ts` (gizmo edits → text: update/add a line in the step at t, split the step if t is mid-step). Saved into the model (`io.edit`, autosaved). `buildTimeline()` seeks the old player to 0 before compiling (compile reads the start pose), then restores t. `Timeline.lines` maps script line → {start, end}.
- Rotation: world-space slerp about a pivot. The default pivot is the targets' bbox centre at their virtual pose; `pivot @x [p]` is stored in the first member's frame, so it follows the part. Don't move and rotate the same part in one parallel block (the last tween wins).

- Right panel tabs: Animation (controls + `.anim`), Illustration (drawing controls + `.draw`), AI Assist.
- AI assist: `src/assist/loop.ts` (manual streaming tool loop on `@anthropic-ai/sdk`, SolverKit's event protocol; model `claude-opus-5-5`, adaptive thinking, `fallbacks: "default"`, cached system prompt; tools use `eager_input_streaming` and are validated before running), `src/assist/system.ts` (system prompt – keep it stable for caching), the chat UI is SolverKit's `AssistPanel`, mounted by `app/src/assist.tsx` via `StudioIO.mountAssist` with an `AssistHost` (`src/assist/host.ts`); our proposal kinds (`script edit`, `groups`, `state`, `shapes`, `copies`, `annotations`, `placement`) are registered there; chats are one message per proposal (`migrateChat` converts old ones). The browser SDK talks to SolverKit's key proxy (`/api/assist/proxy`); the app server reads the key from the repo's `.env`. Never expose the key to the page. Every change the assistant makes is a proposal the user accepts. Assist targets resolve like scripts (`resolveIds`: ids, globs – without `/` also over short names – @groups, unique short names / display names). Read tools (`src/assist/tools.ts`): find_parts, get_part, get_tree, check_script (dry-run: seek 0, compile, restore t), screenshot (off-screen framed view, JPEG). Proposal tool `propose_script_edit` (full new script → `proposal` event with base text, compile check and errors); app/src/assist.tsx renders the card (SolverKit TextDiffCard, which flags a script changed since `base`; Preview = compile the proposal into the player without touching the editor), Accept = `AssistHost.accept` → `scriptPanel.setText`. `?debug=proposal` injects a sample card. `propose_groups` / `propose_state` / `propose_shapes` / `propose_placement` (in `modelProposeTools`; placement: `planPlacement` in studio.ts works out one rigid world transform at t = 0 – rotate about a pivot, then move_by / move_to an anchor of the box – and `applyPlacementChanges` writes placements (shapes: their own numbers) then `applyPlacements` + `buildTimeline({ atStart: true })` with no seek in between, refreshing locked parts' matrices) validate against the scene (shapes: named sizes per kind from `sizeKeys`, update merges onto the current shape, rename; the card shows the full new `ShapeDef`; Accept → `applyShapeChanges` → `syncShapes`); Accept calls `applyGroupChanges` / `applyStateChanges` in studio.ts (same semantics as the tree: ancestor-covered members dropped, explicit flags with descendants inheriting; state also covers colour, remove/restore and keep_uncut), autosaves, recompiles. `?debug=model-proposals` exercises both. The conversation persists in the model's `chat` (debounced). `?debug=assist` runs the read tools and dumps results into `<pre id=debug>` for headless checks.

- Hidden-line mode: `src/view/drawing.ts` – normal+depth pass (scene.overrideMaterial = `partPassMaterial('normals')` from caps.ts: rgb = normal, alpha = part id set per mesh in `onPartRender` – a ShaderMaterial, since three only re-uploads built-in materials' uniforms when the material changes; with the cutaway clip planes; edge lines, outline hulls, sprites and the gizmo hidden for that pass) then a full-screen edge shader: anti-aliased coverage per line type (silhouette = background or a depth departure from the plane through the opposite neighbour, weight `silThickness`; edge = crease or part-id change, weight `thickness`). `drawFrame()` in studio.ts picks shaded or drawing; PNG export renders one frame at 2× pixel ratio.


- Base colours: `model.colors` (id or @group → #hex). `applyColors()` in studio.ts clones the material per coloured mesh (`userData.baseMat0` keeps the original, `ownMat` set so the compiler doesn't clone again; respects the selection highlight's `origMat`). Changing them: seek 0, apply, `buildTimeline({ atStart: true })` (the old player's reset would overwrite the new colours). Script `color T #hex|reset [dur]` compiles to `highlight`; `reset` goes to the object's base colour (VState.base).

- Removed parts / display names: `model.removed` (ids) and `model.labels` (id → name), per animation. Removed objects get `userData.removed`: invisible (all visibility formulas include it), suppressed in `reconcile`, filtered from tree/assist, and `compile(..., isRemoved)` refuses them (groups skip removed members). Quick-fixes in `buildTimeline`: Restore (removed), Undo delete (`tree.lastDeletedGroup`), Unlock (locked). Group rename rewrites `@old` in the script via `onGroupRename` before the groups change.

- Targets: comma-separated lists (`a, b, @g`) parse to arrays; a target that isn't an id/glob/@group resolves by unique short name (last id segment) or label (`byName` in compile.ts; ambiguous → error). Pick mode: `ScriptPanel.updatePick` arms when the cursor is in a step's target position; tree `onSelect(…, clicked)` → `insertTarget(shortSpec(spec), add)`.

- Lists/loops: `list @x = …` (compile.ts `lists`, checked against tree groups) and `each T [stagger d] [order o] { … }`: compiled per item with `$` swapped for the id and `$i` as an expression var (vector components may be `{… $i …}`); only the first item records `Timeline.lines` (`recordLines`). Globs without `/` also match short names, natural-sorted.

- Section caps (`src/view/caps.ts`): per cut plane, the parts (materials with `userData.capped`, set by `withCaps`) are drawn additively into 32-bit float targets with `partPassMaterial('capSum')` (clipped by that plane only, no depth test): back faces add the part's colour/id and 1, front faces subtract them – what remains is the part(s) containing the point on the plane (parts wholly behind cancel, overlaps average). A quad on the plane draws sum/count where count ≠ 0 (real depth), taking the most common count in a 3×3 neighbourhood (a buried part's silhouette pixel can count one side only – GPU edge tie-breaking). Per-mesh values come from `onPartRender` (ShaderMaterial overrides). Needs outward winding. Call `withCaps` on every new/cloned part material.

- Undo/redo (studio.ts): `docNow` is a deep copy at load (the live store shares the model's snapshots / groups / folders objects – sharing them let the first change after opening write into the saved "before"). `applyPlacements` ends with `refreshWorld(built.root)`: world matrices from local ones regardless of the locked flags (locked CAD skips three's update, so undo / placement changes stayed drawn at the old pose). Every change goes through `edit()`, which records the prior `docNow` (colors, snapshots, groups, labels, removed, script, views, keyframe) once per 400 ms burst; `restoreDoc` reapplies a state in place. Script typing (`change(text, typed=true)`) is the editor's own undo and strips `script` from older entries. New persistent state must be added to `UNDO_KEYS` and `restoreDoc` (and `MODEL_FIELDS` in the server, the schemas and `ORDER` in file.ts).

- CAD tool (📦, `.cadpop`): lists `scene.cad_models`, adds a vault `CAD/*.glb` (`io.files.list`, SolverKit `GET /api/files?folder=`) or uploads one (`io.files.upload`, XHR PUT with progress, 409 → confirm overwrite), removes one; id from the file name, `up: 'y'`, the first `ground: true`. Changing `scene` needs a remount: `io.reload()` (app/src/studio.tsx mounts from `written`, since the frame may not have applied the edit yet) – Set origin uses it too. An empty animation (no CAD, no shapes) shows a Load-a-CAD-model prompt. The app server resolves the vault path (SolverKit's file listing fails through symlinks).
- Remove / Keep only (tools bar; `removeSelection`, `keepOnly` → `setRemoved`): Keep only walks from the root, keeping ancestors of the selection and removing the top-most other registered parts. CAD panel pose: `setCadPose` writes `scene.cad_models[i].position` / `rotation_deg[1]` and re-poses the loaded model in place (`poseModel` in cad.ts, shared with loading; locked CAD needs its matrix updates switched on for the change), then copies rebuild. ✂ Slim (`slimCad` → `src/scene/slim.ts` `slimGlb`, browser-side: three's GLTFLoader `parser.associations` maps our ids to node / primitive indices, gltf-transform (core/functions/extensions, lazy-loaded) empties those nodes – kept as placeholders so sibling `#n` ids don't shift – prunes and writes; uploads `CAD/<name>-slim.glb`; switching bakes a grounded model's offset into its position).
- Gizmo: at t = 0 it attaches to locked parts too (start pose; their matrix updates are switched on for the drag, `reconcile` re-locks after); later times only unlocked (script edits). Ctrl/⌘ at the last pointerdown on the canvas (`downMods`) makes the drag a copy: the drag D (world) becomes a new copy (`of` = selected specs, or a copy's own sources with its pose composed) and the originals go back. Alt held = rotate mode + 15° snap until released (restored after the drag ends, on `dragging-changed`, which fires after three's `mouseUp`). Tool buttons `gmove` / `grot` (`setGizmoMode`). On macOS Ctrl-click is a right-click – ⌘ is the copy modifier there.
- Annotations (`src/view/annotations.ts` `AnnotationLayer`; model `annotations`: id, title, note, target = part ids / @group / list / `folder:Path`, anchor {part, local} in that part's frame (absent → the target's box centre), offset m, show): HTML cards over the canvas + an SVG of leaders, projected each frame (`annLayer.update()` after drawFrame); the studio's `anchor` hook gives the world point and visibility (shown, not cut). ✎ Annotate / tree Annotate… → `startAnnotate` (target from the selection; folder → `folder:<path>`), the next canvas click (`annotPick`, before the gizmo check; gizmo detached) → `finishAnnotate` (anchor = nearest registered ancestor of the hit, its local point). `annotationParts` resolves folders now (their groups and sub-folders'). Folder / group renames rewrite targets (tree `onFolderRename`, `onGroupRename`). Undoable (`UNDO_KEYS`). Every change goes through `saveAnnotations()` (edit + cards + list). The list is the tree's Notes column (tree.ts `notes` hooks, ✎ Notes in its header, `notesOn` in localStorage; `#tree.notes` is 220 px wider and above the view bar; `.notes-open` on the studio root moves the tools bar, tree toggle, chapter / clock, view bar and triad (`leftPanelsW`)): a row's key is its id, `@group` or `folder:path`; `notesOf(key)` = annotations whose target is exactly that; the title is edited in a floating input (`editNote` – rows are redrawn as the tree scrolls); `noteTitle` renames / adds (target = the key, the centre) / deletes on empty; `refreshAnnList` = `tree.redraw()`. A hidden part hides its annotation in the layer whatever `show` says (only the open editor overrides), CSV (`exportAnnotationsCsv`), `frameObjects` (fit their box from the current direction). Assist: `get_annotations`, `propose_annotations` (tools.ts `annotationChanges`; deps `annotations` / `annotationTarget`) → `applyAnnotationChanges` (a point anchors on the target's mesh nearest to it). Script `annotate SEL on|off [dur]` (anim.ts → compile `annotate` StepEvent; `compile(…, annotationsMatch)` errors on a selector matching none) → `resolveAnnSteps` after each compile / annotation change (`annotationsFor`: "Title", id, all, same target, or overlapping parts) → `annOpacity(a)` at the playhead (each step in order, fading over its duration; 1 with no steps) → the layer's `opacity` hook. `annSteps` is declared before the first compile. Sheets: `.draw` `annotate on` → `sheetCallouts(ctx)` (shown, on at the sheet's time, anchor visible at its pose, not all parts in hide / outside only) → `makeDrawing({ worldCallouts })` maps world → drawing units like hlr (NDC × half frame) → `toSvg` layer `annotations` (`CALLOUT` sizes, `calloutBox` kept in the area, `leaderEnd`); `renderSheetPng` draws the same on its canvas through the sheet's ortho camera.
- Window / crossing select (`src/view/boxSelect.ts` `partsInRect`; wiring in studio.ts): Shift-drag on the canvas – a capture listener on the canvas's parent stops OrbitControls and click-to-pick; bounding boxes decide most meshes, else vertices (window: all inside) or triangles (crossing: any touching). Candidates: registered, visible, not removed meshes (not outline hulls).
- Tools bar (studio.ts, `#toolsbar`): blank / blank others / show all, select by name (`partsNamed`, same match as script `~text`), set origin (`src/scene/origin.ts`: vertical cylinder fit from vertex normals + a flat face's height → `setOrigin` shifts `scene.cad_models` positions, views and snapshot cameras; the studio remounts), thumbnail, views (`model.views`; script `camera <name>`), group.
- Shapes (basic modelling, `src/scene/shapes.ts`): `model.shapes` (`ShapeDef`: id, kind, size, position, rotation°, colour, optional linear/circular `array`). `buildShapes()` in studio.ts rebuilds them under a registered `shapes` group: part `shapes/<id>`, array copies `shapes/<id>/<id>-<i>`; home pose = the shape's own numbers. `syncShapes()` rebuilds in place after an edit (placements, colours, reconcile, tree, timeline) and saves. A shape moved with the gizmo at t = 0 writes its own position/rotation (not a placement). Renames rewrite the script (`renameShapeRefs`). Solids are closed (tube and hex are extrusions), so caps work; `plane` isn't capped. Shapes aren't CAD, so they start unlocked. The Shape panel (`refreshShapePanel`) doesn't re-render while focused on the same shape.
- Linked copies (`src/scene/copies.ts`, model `copies`: id, of [targets], position = the copy's centre, rotation°): `buildCopies()` in studio.ts clones the sources' subtrees (shared geometry, base materials; removed parts skipped; suppressed CAD restored for the clone) under the registered `copies` group: `copies/<id>`, inner parts `copies/<id>/<source id>` (`userData.copyOf`); local = (sources' box centre)⁻¹ × source world. Built in order (a copy may copy an earlier one), after CAD and shapes. Short names inside copies are not resolvable (compile `byName`, `resolveIds`) – the originals keep theirs. `syncCopies()` rebuilds (seek 0, placements, colours, reconcile, tree, timeline) – also when removed parts / groups change (setRemoved, restoreDoc). Gizmo at t = 0 on a copy root writes its own position/rotation. `mirror` = a scaled −1 group inside (three flips the face winding for negative determinants; drawing `collect.ts` flips index order); `array` members `copies/<id>-<i>` (`memberOffset`: world linear step, or turns about a vertical axis), their parts `copies/<id>-<i>/<source id>`; a name clash (another copy called <id>-<i>) is reported in the panel. Duplicate: ⧉ tool, ⌘D, tree menu (`onDuplicate`) – in place, then the copy is selected (gizmo attached directly as a fallback) in Move mode; Copy panel `.cppop` (refreshCopyPanel; shown only while `copyPanelOn` – set by tree **Edit copy…**, cleared by ✕ / Esc – and a copy is selected). Assist `propose_copies` (tools.ts `copyChanges`: position = centre, or offset from the sources' centre via `sourcesCentre`) → `applyCopyChanges`; `applyPlacementChanges` writes a copy root's own numbers. Align tool (`.alpop`, `alignMove` → `planPlacement` + `applyPlacementChanges`; ⌖ Pick = the next selection sets the target and the selection goes back, `alignPicking`). Gizmo snap: `snap` (localStorage) → `setTranslationSnap` / `setRotationSnap`.
- `app/src/studio.tsx` tracks what the studio wrote in `written` (each patch accumulates): the frame applies edits asynchronously, and building on its model during a burst of edits made the studio's own change look like an outside one (a remount).
- Thumbnails: `thumbFrame()` = a script `thumbnail` step, else `model.keyframe` (t, camera, mode), else t = 0; `renderThumb()` renders it off-screen at 480×300 (restoring the view) and sends an <svg> wrapping the JPEG through `io.putThumb`; re-rendered 2 s after edits in `THUMB_KEYS`.
- Outlines (`src/view/glow.ts`, script `outline`): tweens set `userData.outline` (`Glow`: colour, width, k) on the target; the Player resets it. `drawFrame` → `glow.update` (outlined meshes on layer `GLOW_LAYER`, grouped into ≤ 4 look slots) → `glow.render`: a mask (half float, max-blended, no depth test – each slot keeps its whole silhouette; line views mark hidden fragments against `drawing.depth`), a row pass and a column+composite pass (glow outside, tint inside where hidden). Shaded views draw the hidden tint as geometry with depth GREATER + stencil. Per-draw values come from `onPartRender` (`glowColor`/`glowK`/`glowSlot`).
- Depth: the renderer uses a logarithmic depth buffer (less z-fighting across the plant) and a stencil buffer; the hidden-line pass decodes log depth (`lin()` in drawing.ts).
- Assist logs and stop-gaps: `runAssist` takes `log` (records: send, request with the new messages, first_event, message_start/delta, each content block whole, response with pings / max gap, tool_call / tool_result, proposal, stall, retry, end) and `sendId` (header `x-assist-send: <id>#<round>`); studio `assistLog` writes them as `Logs/assist/<animation>/<id>.jsonl` via `io.files.upload` (every 2 s and at close). The server's `AssistProxyLog` ASGI middleware (app.py) appends `Logs/assist/proxy.jsonl` per proxied request. Watchdog: no stream event for `ASSIST_STALL_MS` (120 s; tests set `window.__assistStallMs`) aborts the request and ends the turn with an error (the panel keeps the proposals). Handover (studio `start`): `handover` records for non-text events, `panel_slow` when the panel takes > 1 s to pull the next one, a `heartbeat` every 5 s (`waiting_for` api | panel), and after `PANEL_STUCK_MS` (60 s; `window.__assistPanelStuckMs`) of the panel not pulling, `panel_stuck` → put back prompt + reply + cards, press the panel's Stop. Log fields: `ms` = since the send; durations are `block_ms`, `round_ms`, `tool_ms`. The writer uploads one at a time, the newest content, 20 s timeout (`log_write_failed`). solverkit-candidate stop-gaps: app/src/assist.tsx wraps every proposal kind in `EarlyDecide` (Accept now / Reject on pending cards → `decidedEarly` by `proposalKey`; the finished card replays the decision; `onAccept` skips ones applied early); studio `start` puts a stopped turn's proposals back into the chat (`made`). Annotations may target copies proposed earlier in the session (`proposedCopies` in tools.ts; change `pending`). The scene summary lists copies and annotations; `get_part` lists a part's annotations (`annotationsOn`). Colours: `assistPalette()` (the scene's named colours + `palette(paletteKey)` swatches) and `colourOf(o)` (shown = its meshes' material colours, not the selection highlight; set = own → an ancestor's → a group's holding it, as `applyColors` layers them) feed the context (Palette / Base colours set / Colours in use), `get_part` and `find_parts` (`color`: #rrggbb | off-palette | set | unset; matches meshes).
- AI assist proposals: `propose_script_patch` (find/replace edits – the fast path) and `propose_script_edit` (whole script) share `propose()` in tools.ts; both compile, list locked parts to unlock, and emit the same `script edit` card. Effort defaults to low (app/src/assist.tsx).

- Drawings (Illustration tab, `src/drawing/`): `collect.ts` gathers visible meshes as world triangles, cut by each material's clip planes (`clipSoup`: split by every plane, drop clipped cells – cut faces become open boundaries); `edges.ts` silhouette / boundary / crease edges per view; `hlr.ts` exact HLR: edges projected and split at crossings with contours that are in front, one BVH ray (three-mesh-bvh) per piece, after a software depth pre-pass (`zbuffer.ts`, ortho only) skips edges every pixel around which is covered, nearer by a margin, by *another* mesh (own-mesh occlusion always gets rays); `sections.ts` section loops of cut meshes (per plane, clipped to the other planes' removed side) → caps (occluder-only soups: in the BVH and depth pass, no edges) and hatch edges (kind `hatch`, laid out in screen space, lifted onto the plane; they neither hide nor split); `fills.ts` part fills: a colour-index buffer at paper resolution (0.25 mm/px) traced into even-odd paths per colour (under the lines). MeshBVH reorders its index in place – hlr.ts gives it a copy so `I`/`triMesh` stay in step; `pdf.ts` SVG → vector PDF (jsPDF + svg2pdf.js, lazy-loaded); `saveAllSheets(only?)` writes SVG + PDF and returns {saved, errors} – `app/scripts/drawings.mjs` (`npm run drawings`) calls it headless against a running app; `svg.ts` layout (area above the title block), paper/scale, chained polylines, ISO layers, a plain title box (title + scale, lower right). `file` in a sheet sets the export file name. `renderSheetPng` (studio.ts) is the fast raster sheet: `withSheet` poses as `runSheet` does, then one `drawFrame(orthoCam)` at the paper's pixels (`dpi`, capped by the GPU) in the sheet's `style`, composited with border + `titleBox` on a 2D canvas; the line pass reads orthographic depth as linear (`logDepth` = 2). Update matrices before framing (a pose change has not rendered yet); a half cut trims cut parts' boxes to the kept side. Preview (`previewSheet(focus)`) renders every sheet with it into `sheetImgs` (thumbnail strip + the chosen one large, `showSheet`), uploading the PNGs; the preview's SVG/PDF buttons run the exact `runSheet`. Live: typed changes (and the cursor entering an unrendered sheet) call `liveSheet` – debounced 300 ms, one render at a time, not uploaded; `DrawPanelHooks.cursor` reports the sheet at the cursor. The `.draw` script (`script.ts`, model `drawings`) is edited in `src/view/drawPanel.ts`; `runSheet` in studio.ts poses (snapshot via useSnapshot+reconcile, seek, applyCut, hide/only) synchronously around `makeDrawing`, then restores the working state. Check speed on the plant (≈6–8 s per sheet).

## Conventions
- Y is up, units are metres, and the core base is at y = 0. The operating floor sits at the vessel flange (`floorY`), and locations are relative to it.
- The machine's origin is the grapple tip.
- Block ids are `R<ring>-<i>/L<n>`, with L0 at the bottom. Hex layout is axial, flat-top.
- Script expressions `{...}` are evaluated with `with(Math)`, so don't name script variables after Math functions (`floor`, `max`, …). The floor height variable is `floorY` for this reason.
- Look and feel: cel-shaded (MeshToonMaterial with a 3-band ramp), black background, black outlines, off-white plus a copper accent. Use the `toon()` helper in build.ts, not Lambert/Standard materials. Colours come from the model's `scene.palette`.
- All dimensions are currently placeholders until the user supplies real numbers.

## CAD
- `data/` holds raw CAD and is git-ignored. Never commit it; the plant STEP is 757 MB.
- `tools/step2gltf.py` (uv inline deps, cadquery-ocp, Python <3.13) has three commands: `tree`, `audit`, `convert`. Parsing the plant model takes about 3 minutes and 6 GB, so run it in the background.
- `convert --split` (`tools/stepsplit.py`, `tools/stepindex.py`) is for files OCCT can't hold in memory (the 4.65 GB Shapr3D export). It indexes the text with an mmap (offset, length, type per record; structure records kept), takes each body's forward closure (forked workers), drops copies (same name base + face/point count, then a rigid transform verified on ALL the body's CARTESIAN_POINTs – vertices alone matched symmetric-looking parts wrongly), writes units as standalone STEPs where each body is a root product named `@@<id>@@` (synthesised PRODUCT…SDR records, styles kept only if they stay inside the unit), converts them with `convert --no-split-bodies --no-reinstance --no-optimize` in child processes, then rebuilds the tree from NAUOs (placement = P2·P1⁻¹ of the ITEM_DEFINED_TRANSFORMATION; nodes get C·L·C⁻¹, C = mm→m + Z-up→Y-up) and attaches body meshes. Canonical bodies OCCT can't mesh get their copies converted separately. Check changes against a normal conversion of the plant (same paths, centroids).
- OCCT's glTF writer does not share meshes between instances, so `convert` re-instances baked copies (principal axes + vertex check), merges faces (one primitive per part), then runs `gltf-transform dedup`. Never use gltf-transform `instance`: it flattens the hierarchy and drops names.

## Testing
- `cd app && npx playwright test`: the end-to-end suite (`app/e2e/app.spec.ts`, ~65 tests, ~6 min) on a fresh temporary
  vault and server (port 6173); `e2e/fixtures/small.glb` is a small CAD model. Run it before committing feature work.
- `npm run test:server`: the server's pytest. `npm run typecheck` after every TS change.
- In the page, `window.__studio` is a debug handle (built scene, player, store, tools, renderer, caps, drawing…) with
  test helpers: `addTestBox`, `addTestStack`, `addTestDowel`, `addTestBuried`, `setOrigin`, `renderThumb`, `thumbFrame`; `scriptPanel.setText(…)` replaces the script.
- Rendering checks: draw a frame (`__studio.drawFrame()`), copy the canvas to a 2D canvas and read pixels; project
  world points with `__studio.camera`. Screenshots of the canvas go to the scratchpad, not the repo.
